# 星河项目部署指南

## 环境与核心启动

本次验收环境为 Windows 和 Python 3.13.3。推荐 Python 3.13；Node 仅在修改和重建前端时需要。锁定依赖是已验证环境的版本快照，跨系统冷安装与离线依赖下载尚未完成验收。

在项目根目录执行 README 的五条启动命令。**先运行 `scripts.init_banking_demo`，不要先复制 `.env.example`**：初始化不会覆盖已有 `.env`，而模板不包含可直接运行的随机密钥。

启动只监听 `127.0.0.1`。在 Chrome/Edge 使用 `http://localhost:5173/banking`。切换端口或来源需要同步 WebAuthn 配置；不要通过绕过浏览器安全警告继续设备认证。

## 三种数据边界

本地余额是虚构账本。账单样例位于 `docs/examples/`，导入不会增加余额。Plaid Sandbox 是第三方独立只读来源，不参与本地转账或理财。默认关闭外部接口，不影响核心合成场景。

## 工作人员复核

初始化生成 `backend/data/private/local-reviewer.token`，由演示管理员在本机读取保管。需要复核时从任务的交接入口进入工作台，输入令牌内容，不含变量名、引号或等号。读取来源后填写决定；批准不会自动执行，客户返回任务后主动恢复。令牌不应交给普通试用者。

初始化只在没有 `.env` 时创建配置；已有身份启用状态不会因为更换环境变量自动恢复。身份管理命令参见 `scripts/manage_banking_identity.py --help`。不要把输出的凭据上传到仓库。

## 设备验证

默认 `BANKING_AUTH_MODE=passkey`。本人在支持 WebAuthn 的 Chrome/Edge 中绑定设备并操作 Windows Hello 或其他认证器。PIN 与生物识别由设备处理，服务端校验签名。设备绑定属于虚构会话，不代表银行实名身份。

卡片解冻与挂失、理财申赎及红色转账需要强验证。内嵌浏览器缺少接口时使用系统浏览器，不能用演示验证码冒充硬件验收。

## 可选模型

在本机 `.env` 配置 `LLM_API_KEY`、`LLM_API_BASE`、`LLM_MODEL`，并设置 `BANKING_LLM_ENABLED=1`。可用 `BANKING_LLM_MODEL` 指定银行分类模型。启用会把用户输入和合成联系人/订阅目录发送到所配服务商；请勿输入真实敏感数据。

模型不持有业务工具。超时或校验失败回退规则；固定合成意图集合中有模糊表达需要模型，因此无模型运行不保证该集合满分。

## 可选 Plaid Sandbox

仅在本机填写 `PLAID_CLIENT_ID`、`PLAID_SECRET` 和独立 `PLAID_TOKEN_ENCRYPTION_KEY`，保持 `PLAID_ENV=sandbox`。通过页面明确同意建立连接后读取。不要使用 Production 凭据；不得将外部读取余额当本地可执行资金。

## 修改前端

```powershell
cd frontend
npm ci
npm run lint
npm run build
```

重建后需重新核验、产生新版本清单与发布包；已有发布清单保留原构建，不要手改摘要掩盖版本变化。

## 常见情况

| 情况 | 处理 |
|---|---|
| `.env` 已有但缺密钥 | 保留现有配置，按本机加密工具配置；不要删除原库重新初始化 |
| 文件完整性检查失败 | 使用未修改的提交包，或为修改后的源码重建并复验 |
| 通行密钥来源不符 | 使用配置一致的 localhost 地址，检查 RP 与来源 |
| 工作人员登录失败 | 核对令牌文件、身份启用状态与短时会话，不使用客户令牌 |
| 操作响应中断 | 先只读核查原操作，不换键反复提交 |
| 外部数据不可用 | 查看来源时间和错误说明，保留成功快照；不假造替代数据 |

## 备份和清理

数据库与密钥分别保管，轮换前停止服务。命令入口 `scripts/manage_banking_storage.py`。Windows 文件 ACL 由管理员配置。停止服务后可删除专为评审新建的演示副本；不要删除用户原始配置或研究数据。
