# 进程中断与隔离备份恢复验收 · 2026-10-29

## 方法

由测试进程为每项创建加密虚构数据库和账户。子进程使用同一临时数据库执行任务，在预算写入、节点及日志保存后但事务提交前调用 `os._exit`，或在事务提交后立即退出。该退出不执行 Python 清理逻辑，后续连接重新打开数据库检查资金、节点与记录，再重试或继续。

故障注入程序只接受项目 `backend/data/` 子目录中的 `test.sqlite3`，拒绝主库。测试不终止用户演示服务，不接触主会话。故障程序纳入验收源码摘要。

## 五项结果

1. 预留提交前退出：预留为 0，节点待办，无已提交预留检查点；继续后仅预留 500 元一次。
2. 预留提交后退出：预留为 500 元，节点已完成；多次调度继续后仍只有一个预留检查点。
3. 释放提交前退出：原预留与未释放状态保留；重新释放可成功。
4. 释放提交后退出：预留为 0；再次请求不会负向重复释放，补偿记录仅一条。
5. 使用 SQLite 备份接口制作隔离加密副本：恢复原任务检查点与 500 元预留，原密钥可读取；缺失密钥返回 503。恢复副本可独立释放预算。本测试不把历史备份恢复成生产活动账本。

专项结果 5/5。首次验收的两个记录计数失败来自测试对密文使用 LIKE，改为读取后解析；另一个错误来自 SQLite 上下文未关闭 Windows 文件句柄，改为显式关闭。原失败日志 `tmp/crash-recovery-tests.log` 与修复后日志分别保留，没有把测试夹具错误表述为资金系统修复。

## 适用范围

证明当前本机 SQLite 任务预留与释放路径在这些进程退出位置的事务一致性。不是物理断电、磁盘损坏、操作系统崩溃、银行外部接口恢复或跨机器容灾测试；不覆盖所有交易类型，也不能证明总体 RTO/RPO。此方法由本项目编写，不属于第三方审计。
