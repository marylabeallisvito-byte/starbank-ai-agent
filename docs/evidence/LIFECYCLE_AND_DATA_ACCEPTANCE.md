# 多业务恢复与外部数据故障验收

日期：2026-10-30。本轮是开发者内部自动化和浏览器仿真验收，不是独立用户试点、真实银行交易或新的硬件认证证明。

## 已修复的缺口

1. **解冻权限不足**：原实现把冻结和解冻均列为黄色。现解冻与挂失均为红色；确认后须验证，再办理。执行端拒绝遗留黄色解冻/挂失预览，不能通过旧授权绕过新策略。已完成旧操作的同键重试仍只读返回结果。
2. **锁定期间恢复提示不准确**：只读恢复现在区分已完成、过期、账户锁定、待确认、待验证和未知状态。前端采用服务端说明，锁定或无法安全继续时不打开办理对话框；查验不会自动执行。
3. **汇率缓存语义缺少复验**：摘要校验之外，复验币种完整性、唯一性、基准、有效正数、观察日期和带时区的获取时间。缺失、NaN、负数、重复、非法日期及未来获取时间均不可用于预算报价；返回不可用而非未处理异常。
4. **外部响应类型过宽**：Plaid 重复/缺失账户标识、异常余额结构、非布尔 pending 不再被转换后接受；限流与超时保留最近成功数据和同步游标，不影响本地资金。

## 新增验收矩阵

`test_banking_lifecycle_matrix.py` 覆盖转账、冻结、模拟申购、取消订阅四类操作。以下每行对四类操作分别执行，方法内包含子场景，不把它们混称为独立用户或独立任务样本。

| 场景 | 实际断言 |
|---|---|
| 成功提交后响应丢失 | 恢复读到完成，未再次提交资金请求 |
| 原幂等键并发重试 | 三个并发响应均成功，同一操作的完成审计恰好一条 |
| 已完成操作换键重试 | 409 拒绝，不产生第二次办理 |
| 授权预览过期 | 恢复显示过期、不可继续，执行拒绝 |
| 跨会话访问 | 恢复及执行均 404，无他人记录泄露 |
| 完成审计写入失败 | 业务状态、资金/持仓和设备授权事务回滚；移除故障后原键可安全重试 |

另测解冻必须强验证、旧黄色授权拒绝、账户锁定恢复说明。设备验证使用测试密钥和真实签名算法，并非真实用户设备测试。

`test_banking_feed_resilience.py` 覆盖七种畸形汇率、三种非法获取时间、五种非布尔交易状态、账户异常及实际适配层的限流和读超时。验收使用合成响应与故障注入，没有主动触发外部真实限流。

新专项共 **12 个 unittest 方法通过**。首次日志 `tmp/lifecycle-first.log` 保留：其中订阅测试夹具曾错误读取响应外层，产生四个测试代码错误；修正为读取 `action` 后再验收。夹具错误不计为产品缺陷，也不将首轮混合失败数宣传为产品准确率。

## 页面验收

隔离临时账户从卡片页明确确认冻结，再打开解除冻结预览，检查红色强验证及设备绑定入口。卡片页权限说明同步；卡片完成状态使用“卡片状态已更新”，订阅完成使用“取消结果已记录”，避免误报为资金入账。

截图与最终结构化验收已保存在 `output/lifecycle-20261030/`。本轮只操作虚构卡片，未调用真实银行接口或请求用户设备签名。

## 保留的边界

- 本矩阵覆盖指定路径；物理断电、跨机器容灾、机构身份及所有定时/跨设备组合尚未验收。
- 理财赎回已有上一轮响应丢失和对账用例，本轮四类矩阵用申购代表，不能声称覆盖全部赎回边界。
- 只读恢复提供下一步指引，不预先保证继续一定成功；执行时仍重新检查余额、图谱来源、适当性和业务状态。
- 本轮改善汇率与 Plaid 数据故障边界；公开通知缓存的全面语义完整性及全部外部接口故障仍需继续检查。
- 新包解压检查仍复用本机虚拟环境；冷安装、其他系统、手机/键盘全面验收仍未完成。
